## 🏆 题目 1：什么是设计模式？设计模式的基本要素有哪些？（2023、2024 连考两年超高频必考题！）

### 满分答题要点（5分）：

1. **设计模式的定义（2分）**：
   设计模式（Design Pattern）是一套**被反复使用、多数人知晓的、经过分类编目的、代码设计经验的总结**。它是为了可重用代码、让代码更容易被他人理解、保证代码可靠性。
2. **设计模式的基本要素（3分，答出以下 4 点）**：
   - **① 模式名称（Pattern Name）**：助记名，用一两个词概括模式的模式意图；
   - **② 问题（Problem）**：描述了应该在何时使用模式，解释了设计问题和问题存在的前因后果；
   - **③ 解决方案（Solution）**：描述了设计的组成部分、它们之间的相互关系、各自的职责和协作方式；
   - **④ 效果（Consequences）**：描述了应用该模式所达到的系统目标以及采用该模式需要付出的权衡代价（优缺点）。

## 🏆 题目 2：简述继承复用与组合/聚合复用的差异及优缺点。（2023、2024 连考两年超高频必考题！）

### 满分答题要点（5分）：

1. **核心差异（实现方式不同，1分）**：
   - **继承复用（类复用）**：通过面向对象的继承机制来实现代码复用，子类继承父类的属性和方法；
   - **组合/聚合复用（对象复用）**：通过将现有类的对象作为成员变量包含到新类中，通过委托调用其方法来实现复用。
2. **继承复用的优缺点（2分）**：
   - **优点**：简单易用，新类容易扩展。
   - **缺点（白盒复用）**：
     - ① 破坏封装性：父类的内部实现细节对子类公开；
     - ② 静态死板：在编译期就已确定，无法在运行时动态改变；
     - ③ 容易产生类爆炸，且父类修改会波及所有子类。
3. **组合/聚合复用的优缺点（2分）**：
   - **优点（黑盒复用）**：
     - ① 维护封装性：成员对象的内部细节不可见；
     - ② 动态灵活：可以在运行期动态传入不同的实现对象进行灵活替换；
     - ③ 降低耦合，避免类爆炸。
   - **缺点**：系统中会有较多的对象需要管理。
4. **结论（总结加分项）**：面向对象设计提倡**合成复用原则（CRP）**，即**尽量使用组合/聚合，少用继承**。

## 🏆 题目 3：讨论组合模式中“透明组合模式”与“安全组合模式”的异同。（2023 期末真题）

### 满分答题要点（5分）：

1. **共同点（1分）**：
   两者都用于将对象组织成树形结构以表示“部分-整体”的层次结构，使得客户端对单个对象（叶子）和组合对象（容器）的使用具有一致性。
2. **核心区别：管理子构件的方法（add、remove、getChild）声明的位置不同（2分）**：
   - **透明组合模式**：
     - 管理子构件的方法声明在**抽象构件（Component）**中；
     - 在叶子构件和容器构件中都具备这些方法。
   - **安全组合模式**：
     - 管理子构件的方法**只声明在容器构件（Composite）**中；
     - 抽象构件和叶子构件中完全没有这些方法。
3. **优缺点对比（2分）**：
   - **透明组合模式**：
     - **优点**：透明性好，客户端完全面向抽象编程，对叶子和容器一视同仁；
     - **缺点**：不够安全，叶子对象调用 `add()` 时无意义，只能抛出异常，错误推迟到了运行期。
   - **安全组合模式**：
     - **优点**：绝对安全，叶子根本没有管理子节点的方法，误调用在编译期就会报错；
     - **缺点**：不够透明，客户端无法完全面向抽象构件编程，必须区别对待容器和叶子。

## 🏆 题目 4：请简单介绍两种常用的代理模式及其应用场景。（2023 期末真题）

### 满分答题要点（5分，任选两种展开）：

1. **保护代理（Protect Proxy）**：
   - **定义**：控制对一个对象的访问权限，给不同的用户提供不同级别的使用权限。
   - **应用场景**：论坛权限控制（已注册用户拥有发帖/删帖权限，游客只能浏览）。
2. **远程代理（Remote Proxy / 大使 Ambassador）**：
   - **定义**：为一个位于不同地址空间（如远程服务器）的对象提供一个本地的代理对象，隐藏网络通信细节。
   - **应用场景**：Java RMI（远程方法调用）、RPC 远程分布式调用中的本地存根（Stub）。
3. **虚拟代理（Virtual Proxy）**：
   - **定义**：对于开销巨大的真实对象，先创建一个较小的虚拟代理占位，当客户端真正需要时才去实例化真实对象。
   - **应用场景**：网页大图加载（大图下载完成前先显示占位加载小图标）。

## 🏆 题目 5：简述开闭原则与依赖倒转原则的定义与联系。（题库核心题）

### 满分答题要点（5分）：

1. **开闭原则（OCP）定义（2分）**：
   一个软件实体应当**对扩展开放，对修改关闭**。即在不修改原有系统源代码的前提下，通过扩展新类来实现新功能。
2. **依赖倒转原则（DIP）定义（2分）**：
   高层模块不应该依赖低层模块，**二者都应该依赖其抽象**；抽象不应该依赖细节，细节应该依赖抽象。核心思想是**针对接口编程，不要针对实现编程**。
3. **两者之间的关系（1分）**：
   - **开闭原则是面向对象设计的终极目标**；
   - **依赖倒转原则是实现开闭原则的核心手段与关键技术**。只有系统各模块之间依赖于抽象层，增加新的具体实现类时才不需要修改现有的代码，从而满足开闭原则。

## 🏆 题目 6：饿汉式单例与懒汉式单例的全面对比。（题库核心题）

### 满分答题要点（5分，表格或条目对比）：

| 对比维度 | 饿汉式单例（Hungry Singleton） | 懒汉式单例（Lazy Singleton） |
| :--- | :--- | :--- |
| **实例化时机** | **类加载时**就立即实例化 | **首次调用 `getInstance()` 时**才延迟实例化 |
| **线程安全性** | ✅ **天生线程安全**（JVM 类加载机制保证） | ❌ **默认不安全**，多线程下需使用 DCL 或同步锁控制 |
| **内存与资源** | 较浪费（若该类从未使用，对象始终占用内存） | 节约内存（实现了真正的延迟加载 Lazy Loading） |
| **执行性能** | 第一次及后续调用速度都非常快 | 首次调用需要进行实例化和锁同步检查，略有开销 |

## 🏆 题目 7：简述策略模式的意图、应用场景与缺点。（题库核心题）

### 满分答题要点（5分）：

1. **意图（1分）**：
   定义一系列算法，将每一个算法封装起来，并让它们可以相互替换。策略模式让算法独立于使用它的客户而变化。
2. **应用场景（2分，答出两点）**：
   - 一个系统需要在多种算法/解决方案中动态选择一种（如不同的打折促销算法、不同的排序算法）；
   - 为了避免在业务类中使用复杂的、多重嵌套的条件选择语句（`if-else` / `switch-case`）。
3. **缺点（2分）**：
   - ① **客户端必须知道所有的策略类**，并自行决定使用哪一个策略类；
   - ② 会造成系统中具体策略类的数量较多；
   - ③ 无法在客户端同时使用多个策略。

## 🏆 题目 8：简单工厂、工厂方法与抽象工厂三种工厂模式的区别。（题库核心题）

### 满分答题要点（5分）：

1. **简单工厂模式（1分）**：
   只有一个具体的工厂类，内部通过 `if-else` 根据参数创建同一种产品等级的不同产品。**缺点是违背开闭原则**。
2. **工厂方法模式（2分）**：
   定义一个抽象工厂接口，每一种具体产品对应一个具体的工厂子类。针对**单一产品等级结构**。**完美符合开闭原则**，但会造成类数量成倍增加（类爆炸）。
3. **抽象工厂模式（2分）**：
   抽象工厂中拥有多个工厂方法，每个具体工厂负责生产**一整套相互关联的产品族**（横向产品等级 + 纵向产品族）。新增产品族符合开闭原则，但新增产品等级违背开闭原则（开闭原则具有倾斜性）。
