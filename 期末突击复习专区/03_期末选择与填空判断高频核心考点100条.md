## 📌 第一部分：面向对象设计原则（1 ~ 20 条）

1. **开闭原则（OCP）**：软件实体应当**对扩展开放，对修改关闭**。（**抽象化**是开闭原则的关键）。
2. **面向对象设计的终极目标**是**开闭原则（OCP）**；实现开闭原则的核心途径是**依赖倒转原则（DIP）**。
3. **“不要和陌生人说话”** / **“各人自扫门前雪，哪管他人瓦上霜”**是对**【迪米特法则（LoD）】**的通俗表述（又称最少知识原则）。
4. **依赖倒转原则（DIP）**要求：高层模块不应该依赖低层模块，二者都应该依赖其**【抽象】**；即**针对接口编程，不要针对实现编程**。
5. 在依赖倒转原则中，将具体类的对象注入到其他对象的方式有三种：**【构造注入】**、**【设值注入（Setter注入）】**和**【接口注入】**。
6. **里氏代换原则（LSP）**核心：在软件中将一个基类对象替换成它的子类对象，程序将**【不会产生任何错误和异常】**。
7. **[判断陷阱]**：正方形继承长方形的问题**【不符合】**里氏代换原则。（判断题：正方形/长方形问题符合里氏代换原则？—— **× 错误**）。
8. **[判断陷阱]**：在程序中随意将父类替换为其子类的做法违反了依赖倒转原则？—— **× 错误**，违反的是**里氏代换原则**。
9. **单一职责原则（SRP）**：一个类应该仅有**【一个引起它变化的原因】**，用于控制类的粒度大小。
10. **接口隔离原则（ISP）**：客户端不应该依赖那些它不需要的接口；类与类之间的依赖应当建立在**【最小的接口】**上。
11. **合成复用原则（CRP / CARP）**：程序开发中应优先使用的是**【组合 / 聚合】**关系实现复用，尽量少用**【继承】**。
12. **继承复用**本质上是**【白盒复用】**，父类修改会波及子类，破坏了封装性；**组合复用**是**【黑盒复用】**，成员对象的内部细节不可见，更具动态灵活性。
13. 设计模式的两大主题是：**【系统复用】**与**【系统扩展】**。
14. 依据模式处理的是类还是对象，模式分为：**【类模式】**（处理类与子类继承关系，静态，在编译期确定）和**【对象模式】**（处理对象间关联聚合关系，更具动态性，在运行期改变）。
15. 大多数设计模式属于**【对象模式】**，因为根据合成复用原则，应尽量使用关联/聚合取代继承。
16. 迪米特法则中对象的“直接朋友”包括：**当前对象（this）**、**方法参数对象**、**当前对象的成员变量对象**、**方法内实例化的对象**。
17. **[判断陷阱]**：类模式中类与子类的关系在运行时刻变化，更具动态性？—— **× 错误**，运行时刻动态变化的是**对象模式**。
18. **[判断陷阱]**：单一职责原则要求接口越细越好？—— **× 错误**，盲目追求单一职责会导致类和接口数量剧增，增加系统复杂度和维护成本。
19. 面向接口编程，在声明变量、方法参数、返回值类型时，尽量使用**【抽象类或接口】**，而不是具体类。
20. 迪米特法则的典型应用设计模式是：**【外观模式（Facade）】**和**【中介者模式（Mediator）】**。

## 📌 第二部分：创建型设计模式（21 ~ 45 条）

21. GoF 23 种设计模式根据目的分为：**【创建型模式】**、**【结构型模式】**和**【行为型模式】**。
22. **不属于** GoF 23 种经典设计模式的是：**【简单工厂模式】**（它只是一种编程习惯）。
23. 简单工厂模式包含三个角色：**【工厂角色（Factory）】**、**【抽象产品角色（Product）】**和**【具体产品角色（ConcreteProduct）】**。
24. 简单工厂模式最大的缺点是：**【系统扩展困难，一旦添加新产品不得不修改工厂类的源代码（违背开闭原则）】**。
25. 工厂方法模式又简称为**【工厂模式】**，也叫**【虚拟构造器模式】**或**【多态工厂模式】**，属于**【类创建型】**模式。
26. 工厂方法模式的核心是**【抽象工厂角色】**，它定义了一个创建对象的接口，而由**【具体工厂子类】**决定实例化哪一个具体产品。
27. 工厂方法模式的优点是**【完全符合开闭原则】**；主要缺点是**【系统中类的个数成倍增加（类爆炸）】**。
28. 抽象工厂模式针对的是**【产品族】**的创建，一个具体工厂负责创建**【一整套相关或相互依赖的产品对象】**。
29. **产品等级结构**是指**【产品的继承结构（同一品类，如都是电视机）】**；**产品族**是指**【由同一个工厂生产的、位于不同产品等级结构中的一组产品（同一品牌，如海尔电视机+海尔洗衣机）】**。
30. 抽象工厂模式对开闭原则具有**【倾斜性】**：增加新的产品族**【完全符合】**开闭原则；增加新的产品等级**【严重违背】**开闭原则。
31. 单例模式的核心三大要点：**【某个类只能有一个实例】**、**【必须自行创建这个实例】**、**【必须自行向整个系统提供这个实例】**。
32. 单例模式是结构**【最简单】**的设计模式，其结构中只包含一个被称为**【单例类】**的特殊类。
33. 单例类的构造函数访问权限必须声明为**【私有（private）】**。
34. 饿汉式单例是在**【类加载时】**就完成了实例化；懒汉式单例是在**【第一次被调用时（getInstance）】**才进行实例化（延迟加载）。
35. 双重检查锁定（DCL）中，修饰单例变量必须使用的关键字是**【`volatile`】**，其作用是**【禁止指令重排序】**和**【保证内存可见性】**。
36. JDK 类库中单例模式的典型应用是：**【`java.lang.Runtime`】**（通过 `Runtime.getRuntime()` 获得唯一实例）。
37. 建造者模式（Builder）的定义：将一个**【复杂对象的构建与它的表示分离】**，使得**【同样的构建过程可以创建不同的表示】**。
38. 建造者模式包含四个角色：**【抽象建造者（Builder）】**、**【具体建造者（ConcreteBuilder）】**、**【产品角色（Product）】**和**【指挥者角色（Director）】**。
39. 在建造者模式中，负责安排复杂对象的建造次序、控制构建流程的是**【指挥者（Director）】**。
40. 建造者模式与工厂模式的区别：工厂模式关注于**【生产哪种产品】**；建造者模式关注于**【零件的逐步构建与装配流程】**。
41. 原型模式（Prototype）的定义：用一个已经创建的实例作为原型，通过**【复制（克隆）该原型对象】**来创建新的对象。
42. 原型模式的简单程度仅次于单例模式，它通过克隆创建对象，**【完全绕过了构造方法】**。
43. 在 Java 中能够实现克隆的类必须实现**【`java.lang.Cloneable`】**标识接口，并重写 `Object` 类的 **【`clone()`】** 方法。
44. **浅克隆（Shallow Clone）**：只复制对象本身和基本数据类型成员，引用类型的成员变量**【只复制引用地址（共享引用）】**。
45. **深克隆（Deep Clone）**：除了对象本身被复制外，包含的所有引用对象也被**【递归复制】**；在 Java 中最常用的深克隆方式是**【利用对象序列化与反序列化（实现 `Serializable` 接口）】**。

## 📌 第三部分：结构型设计模式（46 ~ 75 条）

46. 结构型模式的定义：关注如何将**【现有的类或对象组合在一起形成更大、更复杂的结构】**。
47. GoF 23 种模式中包含 **【7 种】** 结构型模式：适配器、桥接、组合、装饰、外观、享元、代理。
48. 适配器模式（Adapter）的意图：将一个类的接口**【转换成客户希望的另一个接口】**，让原本接口不兼容的类可以一起工作。
49. 适配器模式包含三种角色：**【目标抽象类（Target）】**、**【适配者类（Adaptee）】**和**【适配器类（Adapter）】**。
50. 适配器模式细分为**【类适配器】**和**【对象适配器】**两种：类适配器采用**【继承】**关系，对象适配器采用**【关联/组合】**关系。
51. **[判断陷阱]**：类适配器模式中，一个适配器可以同时适配多个适配者？—— **× 错误**，受 Java 单继承限制，一次只能适配一个类；对象适配器才可以同时适配多个适配者。
52. 缺省适配器模式（Default Adapter）：当不需要实现一个接口的所有方法时，先设计一个**【抽象类实现该接口，并为每个方法提供空实现】**，子类只需选择性覆盖。
53. 桥接模式（Bridge）的意图：将**【抽象部分与它的实现部分分离（解耦）】**，使它们都可以**【独立地变化】**。
54. 桥接模式的核心动机是解决系统中存在**【两个独立变化的维度】**，用**【动态组合关联】**取代**【多层静态继承】**，避免子类爆炸。
55. 桥接模式的四个角色：**【抽象类（Abstraction）】**、**【扩充抽象类（RefinedAbstraction）】**、**【实现类接口（Implementor）】**和**【具体实现类（ConcreteImplementor）】**。
56. 毛笔与蜡笔的故事：3 种型号 + 12 种颜色，蜡笔需要 36 支（继承爆炸），毛笔只需要 3 支毛笔 + 12 盒颜料 = 15 个类，这是**【桥接模式】**的典型比喻。
57. 桥接模式在工业界最经典的应用是：**【Java JDBC 驱动程序】**。
58. 装饰模式（Decorator）的意图：**【动态地给一个对象增加一些额外的职责（功能）】**，比生成子类更为灵活。
59. 装饰模式的四个角色：**【抽象构件（Component）】**、**【具体构件（ConcreteComponent）】**、**【抽象装饰类（Decorator）】**和**【具体装饰类（ConcreteDecorator）】**。
60. 抽象装饰类（Decorator）的代码特征是：**【既继承了抽象构件，又在内部聚合了一个抽象构件的引用】**。
61. 装饰模式在 Java 类库中最经典的应用是：**【Java I/O 流体系（如 `BufferedInputStream(FileInputStream)`）】**。
62. **透明装饰模式**：客户端完全针对抽象编程，可以实现**【多层嵌套装饰】**，但不能单独调用具体装饰类新增的业务方法。
63. **半透明装饰模式**：用具体装饰类型来定义对象，可以调用新增函数，但**【无法实现对同一个对象的多次装饰】**。
64. 组合模式（Composite）的意图：组合多个对象形成**【树形结构】**以表示**【“部分-整体”】**的层次结构，使客户端对单个对象和组合对象的使用具有**【一致性】**。
65. 组合模式包含三个角色：**【抽象构件（Component）】**、**【叶子构件（Leaf）】**和**【容器构件（Composite）】**。
66. 组合模式在 Java 类库中最经典的应用是：**【AWT / Swing 的 GUI 构件（`Component` 与 `Container`）】**。
67. 杀毒软件对文件和文件夹查杀病毒、操作系统目录结构遍历，使用的都是**【组合模式】**。
68. 外观模式（Facade）的意图：为子系统中的一组接口提供一个**【统一的入口（高层接口）】**，使得子系统更加容易使用。
69. 外观模式中，客户端只与**【外观角色（Facade）】**进行交互，完全不需要知道子系统内部各个类的交互细节。
70. 外观模式是**【迪米特法则】**的最典型体现。
71. 代理模式（Proxy）的意图：给某一个对象提供一个**【代理】**，并由代理对象**【控制对原对象的引用】**。
72. 代理模式包含三个角色：**【抽象主题（Subject）】**、**【真实主题（RealSubject）】**和**【代理主题（Proxy）】**。
73. 常见的代理模式类型：**【远程代理】**（如 RMI）、**【虚拟代理】**（大图加载）、**【保护代理】**（论坛权限控制）、**【缓冲代理】**（结果缓存）。
74. Spring 框架中的 AOP（面向切面编程）技术底层使用的是**【动态代理（Dynamic Proxy）】**。
75. 适配器模式 vs 装饰模式 vs 代理模式辨析：
   - 适配器模式的用意是**【改变接口】**；
   - 装饰模式的用意是**【保持接口并增强功能】**；
   - 代理模式的用意是**【保持接口并控制访问】**。

## 📌 第四部分：行为型设计模式（76 ~ 100 条）

76. 行为型模式的定义：关注系统中**【对象之间的相互通信、交互协作和职责分配】**。
77. 策略模式（Strategy）的意图：定义一系列算法，将每一个算法**【封装起来】**，并让它们可以**【相互替换】**。
78. 策略模式包含三个角色：**【环境类（Context）】**、**【抽象策略类（Strategy）】**和**【具体策略类（ConcreteStrategy）】**。
79. 策略模式的核心优点是**【完美支持开闭原则】**和**【避免多重条件转移语句（if-else）】**；主要缺点是**【客户端必须知道所有的策略类，并自行选择】**，且**【无法在客户端同时使用多个策略】**。
80. 策略模式在 Java GUI 中的典型应用是：**【容器布局管理器（`LayoutManager`）】**。
81. 状态模式（State）的意图：允许一个对象在其**【内部状态改变时改变它的行为】**，对象看起来似乎修改了它的类。
82. 状态模式的关键是引入了一个**【抽象状态类（State）】**来专门表示对象的状态，每个具体状态类封装了该状态下的特定行为与状态切换逻辑。
83. 状态模式把庞大的 `switch-case` 状态判断矩阵，拆分到了各个独立的**【具体状态类】**中。
84. **策略模式 vs 状态模式辨析**：
   - 策略模式中策略之间**【彼此独立】**，由**【客户端主动选择】**；
   - 状态模式中状态之间**【存在流转依赖（状态机）】**，由**【环境类或状态对象自动切换】**，客户端被动使用。
85. 观察者模式（Observer）的意图：定义对象间的一种**【一对多依赖关系】**，使得每当一个对象状态改变时，其相关依赖对象皆得到通知并被**【自动更新】**。
86. 观察者模式的别名包括：**【发布-订阅（Publish/Subscribe）模式】**、**【模型-视图（Model/View）模式】**、**【源-监听器（Source/Listener）模式】**。
87. 观察者模式包含四个角色：**【抽象目标（Subject）】**、**【具体目标（ConcreteSubject）】**、**【抽象观察者（Observer）】**和**【具体观察者（ConcreteObserver）】**。
88. 经典 MVC 架构中，**【Model 充当观察目标】**，**【View 充当观察者】**，Model 数据改变自动通知 View 刷新。
89. Java 的 GUI 按钮事件监听模型（`Button.addActionListener`）基于**【观察者模式】**。
90. **[判断陷阱]**：观察者模式中，观察者被调用时可以知道目标对象是怎么发生变化的？—— **× 错误**，观察者只能知道目标发生了变化，并不知道变化的具体细节（除非额外传参）。
91. 迭代器模式（Iterator）的意图：提供一种方法**【顺序访问一个聚合对象中的各个元素】**，而又**【无需暴露该对象的内部表示】**。
92. 迭代器模式又称为**【游标（Cursor）模式】**，属于使用频率最高的行为型模式之一。
93. 迭代器模式实现了**【数据存储】**与**【数据遍历】**的分离，数据存储由聚合类负责，遍历由迭代器负责，符合**【单一职责原则】**。
94. 迭代器模式的四个角色：**【抽象迭代器（Iterator）】**、**【具体迭代器（ConcreteIterator）】**、**【抽象聚合类（Aggregate）】**和**【具体聚合类（ConcreteAggregate）】**。
95. Java 集合框架中的 `java.util.Iterator`、`Collection` 体系以及增强 `for` 循环（foreach）底层就是**【迭代器模式】**。
96. 命令模式（Command）的意图：将一个**【请求封装为一个对象】**，从而可用不同的请求对客户进行参数化，对请求排队或记录日志，并支持**【可撤销（Undo）的操作】**。
97. 命令模式又称为**【动作（Action）模式】**或**【事务（Transaction）模式】**。
98. 命令模式的四个角色：**【抽象命令类（Command）】**、**【具体命令类（ConcreteCommand）】**、**【调用者/请求发送者（Invoker）】**和**【接收者（Receiver）】**。
99. 命令模式的优点是将**【请求发送者与请求接收者解耦】**；缺点是**【具体命令类的数量过多】**。
100. 组合模式与命令模式联用可以产生**【宏命令（Macro Command / 组合命令）】**，实现批处理；Java 多线程中的 **【`Runnable` 接口】** 和 **【线程池 `ThreadPoolExecutor`】** 是命令模式最顶级的体现。
