## 一、`练习题(1).docx` 全题精解（创建型与基础原则专题）

> **原文件**：`试卷/详细设计/练习题(1).docx`（共 20 道选择 + 5 道填空 + 3 道编程题；以创建型模式与开闭/单一职责为主）。

### （一）选择题（20 题）

1. **面向对象设计中的“开闭原则”指的是：**
   - A) 类应该对扩展开放，对修改关闭 &nbsp; B) 类应该对修改开放，对扩展关闭 &nbsp; C) 类应该既对扩展开放也对修改开放 &nbsp; D) 类应该既不对扩展开放也不对修改开放
   - **答案**：`A`

2. **在简单工厂模式中，负责创建对象的角色是：**
   - A) 客户端 &nbsp; B) 抽象工厂 &nbsp; C) 具体产品 &nbsp; D) 工厂
   - **答案**：`D`（具体由工厂类 `Factory` 中的静态方法根据参数创建产品）

3. **下列哪个不是工厂方法模式的优点？**
   - A) 提高系统的灵活性 &nbsp; B) 符合开闭原则 &nbsp; C) 减少系统中类的数量 &nbsp; D) 易于扩展
   - **答案**：`C`（**反了**：每加一个具体产品就要成对加一个具体工厂，会使系统中类的个数成对增加）

4. **抽象工厂模式最适合用于：**
   - A) 创建单个对象 &nbsp; B) 创建一系列相关或依赖对象 &nbsp; C) 创建复杂对象 &nbsp; D) 创建不可变对象
   - **答案**：`B`（即“产品族”）

5. **建造者模式的主要优点之一是：**
   - A) 支持多态 &nbsp; B) 可以创建不同类型的对象 &nbsp; C) 分离对象构造和表示 &nbsp; D) 减少代码重复
   - **答案**：`C`

6. **下列哪个不是面向对象设计的原则？**
   - A) 单一职责原则 &nbsp; B) 开闭原则 &nbsp; C) 接口隔离原则 &nbsp; D) 高内聚原则
   - **答案**：`D`（“高内聚低耦合”是模块设计目标，不是 6+1/SOLID 具体设计原则名称）

7. **在简单工厂模式中，如果需要添加新的产品类，应该如何处理？**
   - A) 修改工厂类 &nbsp; B) 不需要修改任何代码 &nbsp; C) 添加新的工厂类 &nbsp; D) 修改所有客户端代码
   - **答案**：`A`（因此简单工厂违背开闭原则）

8. **抽象工厂模式与工厂方法模式的主要区别在于：**
   - A) 抽象工厂模式可以创建多个相关对象 &nbsp; B) 抽象工厂模式不能创建对象 &nbsp; C) 工厂方法模式只能创建单一对象 &nbsp; D) 抽象工厂模式更简单
   - **答案**：`A`（注：严密表述是抽象工厂面对多个产品等级结构/一族相关产品，工厂方法针对单个产品等级结构）

9. **建造者模式中，构建过程通常由谁来执行？**
   - A) 客户端 &nbsp; B) 构建器 &nbsp; C) 导演者 &nbsp; D) 产品
   - **答案**：`C`（`Director` 导演者/指挥者控制构建步骤与顺序，调用 `Builder` 的各 `buildPartX()` 方法完成装配）

10. **下列哪个设计模式最适合用于创建具有复杂内部结构的对象？**
    - A) 简单工厂模式 &nbsp; B) 工厂方法模式 &nbsp; C) 抽象工厂模式 &nbsp; D) 建造者模式
    - **答案**：`D`

11. **在工厂方法模式中，如果需要新增一个产品类，通常需要：**
    - A) 修改现有的工厂类 &nbsp; B) 创建一个新的工厂类 &nbsp; C) 修改现有的产品类 &nbsp; D) 不需要做任何修改
    - **答案**：`B`（新增“具体产品类 + 对应具体工厂类”）

12. **在工厂方法模式中，具体工厂实现接口来创建具体产品，这体现了什么设计原则？**
    - A) 单一职责原则 &nbsp; B) 开闭原则 &nbsp; C) 里氏替换原则 &nbsp; D) 接口隔离原则
    - **答案**：`B`（扩展新工厂即可生产新产品而不修改原有工厂代码；注：若选项有“依赖倒转”也相关，四选一按课程题库重点选 `B`）

13. **当系统需要创建一系列相关或依赖对象时，最好使用哪种设计模式？**
    - A) 简单工厂模式 &nbsp; B) 抽象工厂模式 &nbsp; C) 建造者模式 &nbsp; D) 工厂方法模式
    - **答案**：`B`

14. **在建造者模式中，如果一个对象的创建过程非常复杂且包含许多可选部分，最好使用哪种模式？**
    - A) 简单工厂模式 &nbsp; B) 抽象工厂模式 &nbsp; C) 建造者模式 &nbsp; D) 工厂方法模式
    - **答案**：`C`

15. **在工厂方法模式中，具体工厂类通常是通过哪个方法来创建具体产品？**
    - A) `create()` &nbsp; B) `build()` &nbsp; C) `construct()` &nbsp; D) `factoryMethod()`
    - **答案**：`D`（对应 GoF/PPT 经典UML中的标准命名 `factoryMethod()`）

16. **建造者模式中的导演者类的作用是什么？**
    - A) 定义产品的组成部分 &nbsp; B) 构建产品的各个部分 &nbsp; C) 控制建造者的构造过程 &nbsp; D) 存储构建完成的产品
    - **答案**：`C`

17. **如果一个系统需要根据不同的条件创建不同类型的产品，而且这些产品的创建逻辑很相似，应该使用哪种模式？**
    - A) 简单工厂模式 &nbsp; B) 抽象工厂模式 &nbsp; C) 工厂方法模式 &nbsp; D) 建造者模式
    - **答案**：`A`（“根据不同参数/条件在一个地方集中切换返回不同产品实例”正是简单工厂的典型定义；若强调“每种产品各自扩展、延迟到子类”才选工厂方法）

18. **在建造者模式中，如果需要创建一个复杂对象的不同变体，通常会：**
    - A) 将所有步骤放在一个方法中 &nbsp; B) 将每个步骤放在单独的方法中 &nbsp; C) 使用静态工厂方法 &nbsp; D) 直接调用产品的构造函数
    - **答案**：`B`（如 `buildPartA()`、`buildPartB()` 分步方法由不同具体建造者分别实现）

19. **工厂方法模式中的抽象工厂类通常定义了一个什么样的方法？**
    - A) 用于创建具体产品的抽象方法 &nbsp; B) 用于创建具体产品的具体方法 &nbsp; C) 用于初始化具体产品的抽象方法 &nbsp; D) 用于销毁具体产品的具体方法
    - **答案**：`A`

20. **在建造者模式中，如果一个对象需要多个步骤来构造，并且这些步骤可能会发生变化，最好使用哪种模式？**
    - A) 简单工厂模式 &nbsp; B) 抽象工厂模式 &nbsp; C) 工厂方法模式 &nbsp; D) 建造者模式
    - **答案**：`D`

#### 编程题 1：根据用户输入创建不同图形（圆形、矩形、三角形）
- **选用模式**：**简单工厂模式**（产品种类固定且少，根据用户传入的类型参数统一创建图形；若考题强调后期频繁加图形则可升级为**工厂方法模式**）。
```java
interface Shape {
    void draw();
}

class Circle implements Shape {
    @Override
    public void draw() { System.out.println("绘制圆形"); }
}

class Rectangle implements Shape {
    @Override
    public void draw() { System.out.println("绘制矩形"); }
}

class Triangle implements Shape {
    @Override
    public void draw() { System.out.println("绘制三角形"); }
}

class ShapeFactory {
    public static Shape createShape(String type) {
        if ("circle".equalsIgnoreCase(type)) return new Circle();
        if ("rectangle".equalsIgnoreCase(type)) return new Rectangle();
        if ("triangle".equalsIgnoreCase(type)) return new Triangle();
        throw new IllegalArgumentException("不支持的图形类型: " + type);
    }
}
```

#### 编程题 2：创建包含文本、表格、图片等元素的复杂 Word 文档
- **选用模式**：**建造者模式（Builder）**（文档由文本、表格、图片等多个部件按步骤组装，符合复杂对象的构建与表示分离）。
```java
import java.util.ArrayList;
import java.util.List;

class Document {
    private final List<String> parts = new ArrayList<>();
    public void addPart(String part) { parts.add(part); }
    public void show() { System.out.println("文档内容: " + parts); }
}

interface DocumentBuilder {
    void buildText();
    void buildTable();
    void buildImage();
    Document getDocument();
}

class WordDocumentBuilder implements DocumentBuilder {
    private final Document doc = new Document();
    @Override public void buildText() { doc.addPart("Word 正文段落"); }
    @Override public void buildTable() { doc.addPart("Word 数据表格"); }
    @Override public void buildImage() { doc.addPart("Word 插图"); }
    @Override public Document getDocument() { return doc; }
}

class DocumentDirector {
    public Document construct(DocumentBuilder builder) {
        builder.buildText();
        builder.buildTable();
        builder.buildImage();
        return builder.getDocument();
    }
}
```

#### 编程题 3：游戏角色生成器系统（建造者模式 + 工厂方法/抽象工厂）
- **原文档参考代码存在的问题**：
  1. 第 1 行 `/ 装备接口` 缺失一个斜杠导致编译失败，且粘入了 `2interface` 等行号垃圾字符；
  2. 题目要求有 `Rogue`（盗贼）、`Ring`（饰品）及 `equipItem`，但原代码漏写了 `Rogue`、`Ring`，并擅自把工厂方法改成了抽象工厂 `EquipmentFactory`。
- **修正后完整可编译代码（补全 `Rogue`/`Ring`，保持清晰可写结构）**：
```java
import java.util.ArrayList;
import java.util.List;

interface Equipment {
    String getName();
    String getDescription();
}

class Sword implements Equipment {
    @Override public String getName() { return "Sword"; }
    @Override public String getDescription() { return "近战利剑"; }
}

class Robe implements Equipment {
    @Override public String getName() { return "Robe"; }
    @Override public String getDescription() { return "轻质法袍"; }
}

class Ring implements Equipment {
    @Override public String getName() { return "Ring"; }
    @Override public String getDescription() { return "暴击饰品戒指"; }
}

// 工厂方法接口：创建具体装备
interface EquipmentFactory {
    Equipment createEquipment();
}
class SwordFactory implements EquipmentFactory {
    @Override public Equipment createEquipment() { return new Sword(); }
}
class RobeFactory implements EquipmentFactory {
    @Override public Equipment createEquipment() { return new Robe(); }
}
class RingFactory implements EquipmentFactory {
    @Override public Equipment createEquipment() { return new Ring(); }
}

// 角色接口与具体角色
interface GameCharacter {
    void equipItem(Equipment item);
    void displayStatus();
}

abstract class BaseCharacter implements GameCharacter {
    private final String roleName;
    private final List<Equipment> items = new ArrayList<>();
    protected BaseCharacter(String roleName) { this.roleName = roleName; }

    @Override
    public void equipItem(Equipment item) { items.add(item); }

    @Override
    public void displayStatus() {
        System.out.println("=== " + roleName + " 装备列表 ===");
        for (Equipment e : items) {
            System.out.println("- " + e.getName() + ": " + e.getDescription());
        }
    }
}

class Warrior extends BaseCharacter { public Warrior() { super("Warrior"); } }
class Mage extends BaseCharacter { public Mage() { super("Mage"); } }
class Rogue extends BaseCharacter { public Rogue() { super("Rogue"); } }

// 建造者模式负责一步步装配角色
interface CharacterBuilder {
    void buildMainEquipment();
    void buildAccessory();
    GameCharacter getCharacter();
}

class WarriorBuilder implements CharacterBuilder {
    private final GameCharacter warrior = new Warrior();
    @Override public void buildMainEquipment() { warrior.equipItem(new SwordFactory().createEquipment()); }
    @Override public void buildAccessory() { warrior.equipItem(new RingFactory().createEquipment()); }
    @Override public GameCharacter getCharacter() { return warrior; }
}

class CharacterDirector {
    public GameCharacter construct(CharacterBuilder builder) {
        builder.buildMainEquipment();
        builder.buildAccessory();
        return builder.getCharacter();
    }
}
```

### （二）填空题（7 题）

1. **`单例`** 模式确保一个类只有一个实例，并提供一个全局访问点。
2. 工厂方法模式定义了一个创建对象的接口，让子类决定实例化哪一个类。工厂方法模式让一个类的实例化延迟到 **`子类`**。
3. 桥接模式将抽象与 **`实现（实现部分）`** 分离，使得两者可以独立变化。
4. **`桥接`** 模式可以使一个类通过继承多个接口来表现多种行为。 *(注：原答案填 `桥接`，但题干表述有 AI 出题瑕疵——严谨地说 Java 类实现多个接口本身就叫多实现，而桥接是通过**对象组合**解耦两个独立变化的维度，考纲仍按 `桥接` 记此练习即可)*
5. 适配器模式通过 **`组合`** 或继承实现将一个类的方法或属性转换为符合另一个接口的期望。
6. 在适配器模式中，目标接口是指 **`客户端（客户）`** 希望调用的接口。
7. 创建型模式关注的是对象的 **`创建（创建过程）`**。

### （三）编程题：文档管理系统（适配器 + 工厂补全）

- **原文档缺漏**：`WordDocument` 未实现 `Document` 接口而提供了 `WordDocumentAdapter`，但缺失了 `ExcelDocument`，且 `DocumentFactory.createDocument()` 方法体完全是空的！
- **完整补全代码**：
```java
interface Document {
    String getContent();
}

class PDFDocument implements Document {
    @Override
    public String getContent() { return "这是PDF文档的内容"; }
}

// 第三方不兼容接口的 Word 类（无 getContent 以外的兼容接口，演示用独立方法 getWordText() 更贴切，保留原方法名亦可）
class WordDocument {
    public String getContent() { return "这是Word文档的内容"; }
}

class ExcelDocument implements Document {
    @Override
    public String getContent() { return "这是Excel文档的内容"; }
}

class WordDocumentAdapter implements Document {
    private final WordDocument doc;
    public WordDocumentAdapter(WordDocument doc) { this.doc = doc; }
    @Override
    public String getContent() { return doc.getContent(); }
}

class DocumentFactory {
    public static Document createDocument(String type) {
        if ("pdf".equalsIgnoreCase(type)) return new PDFDocument();
        if ("word".equalsIgnoreCase(type)) return new WordDocumentAdapter(new WordDocument());
        if ("excel".equalsIgnoreCase(type)) return new ExcelDocument();
        throw new IllegalArgumentException("未知文档格式: " + type);
    }
}
```
