# 建造者模式（Builder Pattern）期末复习笔记

---

## 📌 一、核心定义（一句话考点）
> **定义**：将一个复杂对象的**构建与它的表示分离**，使得**同样的构建过程可以创建不同的表示**。
>
> 💡 **核心地位**：**GoF 23 种设计模式之一**（属于**对象创建型**模式，最复杂的创建型模式，难度等级：★★★★★）。
> - 一句话本质：**“标准化流水线，分步骤装配复杂对象”**。
> - 核心解决痛点：当一个对象由多个零部件组成（如自行车有车架、车座；汽车有发动机、轮胎、底盘），且这些零部件的装配顺序有严格要求时，通过建造者模式实现精细化分步构建。

## 💡 三、四大核心角色（期末必背）

| 角色名称 | 英文 | 本工程对应类 | 通俗比喻 | 职责说明 |
| :--- | :--- | :--- | :--- | :--- |
| **产品角色** | Product | [`Bike.java`](demo1/Bike.java) | 复杂成品（自行车） | 包含多个部件的复杂复合对象。 |
| **抽象建造者** | Builder | [`Builder.java`](demo1/Builder.java) | 工人规范标准 | 规定生产各个零部件的抽象方法（如 `buildFrame()`、`buildSeat()`）以及交付成品的方法 `createBike()`。 |

| **指挥者角色** | Director | [`Director.java`](demo1/Director.java) | **工程总指挥 / 车间主任 / 流水线** | **负责控制构建算法和组装顺序**。严格按照流水线步骤指挥工人干活，并最终交付产品。 |

## ⚖️ 四、优缺点与设计原则

### 优点：
1. **构建与表示解耦**：客户端无需知道产品内部的零部件组成与装配顺序；
2. **良好的扩展性（符合 OCP）**：每一个具体建造者都相互独立，新增具体建造者无需改动已有代码；
3. **更精细地控制产品创建过程**：通过指挥者分步组装，避免漏装或顺序混乱。

### 缺点：
1. **适用范围受限**：所创建的产品必须具有较多的共同零部件，差异太大的产品不适合使用建造者模式；
2. **类数量较多**：若产品内部零件变化复杂，会导致具体建造者类数量剧增。

---

## 🥊 五、建造者模式 VS 工厂模式

- **工厂模式（Factory）**：关注**“生产出什么产品（整体）”**，只要造出来就行，不关心里面怎么造出来的；
- **建造者模式（Builder）**：关注**“复杂产品各零部件如何一步一步被装配出来（流程与细节）”**。
