# 工厂模式家族（Factory Patterns）期末复习与全景对比

---

## 📌 一、工厂模式总览
在面向对象设计中，**“工厂”**指的是专门负责生产/创建对象的类或接口，其核心目的是**将对象的创建与对象的使用解耦**，从而提高系统的灵活性与可维护性。

本课程共涉及三种工厂模式：
1. **[简单工厂模式（Simple Factory）](simple_factory/README.md)** *(非 GoF 23 种设计模式之一)*
2. **[工厂方法模式（Factory Method）](factory_method/README.md)** *(GoF 类创建型模式)*
3. **[抽象工厂模式（Abstract Factory）](abstract_factory/README.md)** *(GoF 对象创建型模式)*

## 🥊 三、三种工厂模式核心差异终极对比（期末必考大题）

| 比较维度 | 简单工厂（Simple Factory） | 工厂方法（Factory Method） | 抽象工厂（Abstract Factory） |
| :--- | :--- | :--- | :--- |
| **GoF 23 种之一？** | ❌ 否（编程习惯） | ✅ 是 | ✅ 是 |
| **模式范围** | 类创建型 | **类创建型** | **对象创建型** |
| **工厂方法性质** | 静态工厂方法（`static`） | 动态方法（分布在具体工厂子类中） | 动态方法（一个工厂类包含多个生产方法） |
| **产品结构特点** | 同一等级结构中的**任意**产品 | 同一等级结构中的**固定**单一产品 | **不同产品族的全部产品**（成套搭配） |
| **增加新产品等级（新产品品类）** | ❌ 需修改工厂方法（**违背 OCP**） | ✅ 增加具体产品+具体工厂（**符合 OCP**） | ❌ **需修改抽象工厂接口及所有工厂子类（违背 OCP）** |
| **增加新产品族（新品牌全家桶）** | 不支持产品族 | 不支持产品族（类爆炸严重） | ✅ **只需增加一套新的具体工厂即可（符合 OCP）** |
| **复杂度与类数量** | 类最少，代码最简单 | 类的数量**成对增加**（类爆炸） | 结构最规范工整，针对产品族设计 |
| **开闭原则评价** | 严重违背开闭原则 | **完全符合开闭原则** | **具有“倾斜性”**（加族符合，加等级违背） |

## 💡 四、核心概念速记：产品等级结构 VS 产品族（填空/选择必考）

- **产品等级结构**：产品的**继承结构**（纵向）。
  - 例如：电视机是一个抽象类，其子类有海尔电视、海信电视、TCL电视，它们构成了**电视机产品等级结构**。
- **产品族**：由**同一个工厂生产的、位于不同产品等级结构中的一组产品**（横向）。
  - 例如：海尔电器工厂生产的海尔电视机、海尔电冰箱、海尔空调，它们来自不同品类，但属于**同一海尔产品族**。
